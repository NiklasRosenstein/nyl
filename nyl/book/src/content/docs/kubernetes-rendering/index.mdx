Kubernetes Rendering turns Helm charts, reusable components, and templates into
plain Kubernetes manifests, from one configuration in Git. `nyl render`,
`nyl diff`, and `nyl apply` share one pipeline, so a local render and a CI
render of the same declaration take [one path](/nyl/start/introduction/#one-declaration-one-path).

This is the first layer. It is the right place to start, and the right place to
stop if Kubernetes is all you deploy. [Kubernetes GitOps](/nyl/kubernetes-gitops/)
builds on it by publishing the rendered manifests to Git.
