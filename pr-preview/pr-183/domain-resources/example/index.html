Example: team-owned AWS accounts

Planned

This walkthrough shows the planned design; none of it runs yet. Field names and commands may change before the slices on the roadmap ship.

5. Know what re-runs

Section titled “5. Know what re-runs”

The unit’s execution key covers the collected content, not where it came from. Where a declaration lives matters only for membership and admission:

ChangeDoes aws-accounts run again?
A team adds or edits an accountYes
A schema default changes an account’s effective valueYes
A declaration moves to another folder under teams/No
A declaration moves into or out of the collection’s pathsYes: it joins or leaves the collection
A declaration moves across a folder the policy treats differentlyYes: admission changes, so the unit is blocked or unblocked
Another team changes its GitHub declarationsNo

A rule that uses oldSelf compares a declaration with its previous version:

8. Use your own pipeline

Section titled “8. Use your own pipeline”

Orchestration is optional. When Terraform or OpenTofu already runs in a CI pipeline, Nyl prepares its inputs, and the pipeline plans and applies as before:

nyl exec without an environment prepares OpenTofu exactly as an orchestrated run would, with the backend, the variables, and its own working copy, and then runs tofu with the arguments after --. The pipeline stays in charge of when to plan and who approves the apply.

Without orchestration, nothing records what was last applied, so every run says what to compare with:

  • --base origin/main in a pull request compares with where the branch forked from main.
  • After the merge, comparing main with itself would detect nothing. --advance names a ref that points at the commit last applied: Nyl compares with it, and moves it to the current commit once tofu apply succeeds. Before running the tool, Nyl checks that it may push the ref and that no newer commit was applied already. If the push still fails, it says so, prints the commands to fix it, and the next run simply checks the changes since the older commit again.
  • The ref is optional and can be a custom ref, a tag, or a branch. The first apply, before the ref exists, passes --bootstrap to run once without a comparison and create it.
  • --no-base skips the comparison deliberately, for local development. Leaving out a base entirely is an error, so a pipeline never skips transition rules by accident.

nyl exec refuses to run uncommitted changes to the files a unit reads unless you pass --worktree, so a local apply never uses inputs that no commit records. --source HEAD runs the committed version instead.

9. Remove access, keep the account

Section titled “9. Remove access, keep the account”

Removing a declaration changes the implementing unit’s input. What happens next is up to the implementation:

  • Revoking an access grant is the everyday case. The team deletes the grant’s declaration, the plan shows the grant leaving the collection and its destroy, and an approval applies it. Removals wait for approval by default.
  • Retiring an account is deliberately harder. prevent_destroy makes the plan fail, so an account is never closed by deleting a file. The platform holds the unit, removes the account from state with nyl exec … -- state rm, deletes the declaration, and resumes the unit.

A hold on a unit protects the unit, not the native resources its next apply removes. Protecting individual resources is the implementation’s job.
