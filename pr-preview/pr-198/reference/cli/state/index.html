Reference/state and lease

state and lease

An Environment keeps its orchestration state in Git: a desired ref and an observed ref, by default the branches nyl/<environment>/desired and nyl/<environment>/observed of the repository its state names. Each operation writes at most one commit per state ref, so the history of those branches is the reviewable record of what Nyl decided and observed.

Note

Orchestration is being built in milestone M3. These commands create, maintain, repair, and delete state; nyl reconcile runs units against it.

See Environments and state for where state lives, how the lease protects it, and which Git hosts support it.

nyl state init

Section titled “nyl state init”

Creates state.yaml on the environment’s state refs. Running it again changes nothing. No other command creates state implicitly; a command against a location without state.yaml exits 1 with NYL-STATE-MISSING and names both ways forward. A state repository Nyl cannot reach or read exits 1 with NYL-STATE-UNAVAILABLE. When a commit outside Nyl changes the environment’s state while a command runs, the command exits 1 with NYL-STATE-CONFLICT; run it again. Commits of environments sharing the ref through path never cause this: Nyl rebases past them.

--fresh starts over deliberately: every unit becomes a new incarnation and executes again at the next reconcile. It is also the way to start over at a location whose state was deleted with nyl state delete: a plain state init there exits 1 with NYL-STATE-DELETED.

nyl state move

Section titled “nyl state move”

Moves state to the location the Environment configures. The options name the old location and each defaults to the configured value: --from (a URL, a GitRepository name, or local), --desired-ref, --observed-ref, --state-path, and --coordination-refs. Units keep their incarnations and receipts.

The history of the state refs moves to the new location, the old location records the move so that every command against it refuses with NYL-STATE-MOVED and names the new one, and only then does the new location become usable. An interrupted move completes when run again. The old refs are kept for audit; removing them is a manual step.

nyl state forget

Section titled “nyl state forget”

Drops a retained tombstone or a pending-teardown unit from state without touching its resources. A unit that returns later starts a new incarnation.

nyl state delete

Section titled “nyl state delete”

Removes an environment’s state, for template instances and declared environments alike, once no unit has an incarnation left. One commit per state ref, with the operation state-delete, removes every file of the environment’s state, including held desired files without an incarnation and records of units whose resources were left in place, and leaves state.yaml with a state-deleted event as the deleted marker. The state refs and their history stay: on a ref shared through path, only the environment’s directory changes, and its own refs keep the history of everything removed. Evidence and signal refs of the environment are deleted.

It refuses, exit 1, while:

  • a unit still has an incarnation, a teardown in progress, or a recorded teardown request (NYL-STATE-DELETE-INCARNATIONS, listing the units and naming --teardown, nyl teardown --unit, and nyl state forget);
  • a run ref no run has imported yet exists, because it may be the only record of units its run created (NYL-STATE-DELETE-INCARNATIONS, naming nyl reconcile -e <env> and nyl recover -e <env>).

--teardown runs nyl teardown --all first and continues to the deletion in the same command, once the state holds no incarnation, no deleting unit, and no recorded teardown request. Otherwise it stops and deletes nothing: exit 2 when every remaining unit waits (a teardown wait, an approval, dependents, readiness, or a held unit that still has an incarnation), and exit 1 when a teardown failed or is uncertain. The teardown’s findings are kept, and its report is under details.teardown. Running the command again resumes. --allow-dependents, --allow-incomplete, and --source <revision> apply to the teardown and require --teardown. A lease broken with nyl lease break whose run is not imported refuses with NYL-LEASE-BROKEN before the teardown.

Every later command for the environment, including reconcile, status, and hold, exits 1 with NYL-STATE-DELETED, naming both ways forward: removing the Environment from source to decommission it, or nyl state init -e <env> --fresh to start it over. A pipeline that still runs the environment fails visibly instead of re-creating anything. Nyl reads the marker from state.yaml, never from commit history.

nyl state reset

Section titled “nyl state reset”

Drops this clone’s local transitions, the commits nyl reconcile --local wrote to the clone’s nyl/<env>/* branches, and moves those branches back to the remote state refs. It writes only the clone’s branches: it takes no lease and never changes remote state, so --local is required.

Forgetting a local receipt can leave resources behind, because the remote state does not record them. When a unit’s receipt or condition in the local view differs from the remote’s, the command lists those units, exits 1 with NYL-STATE-RESET-UNDISCARDED, and proceeds only once --discard <unit>… (repeatable or comma-separated) or --discard-all covers them. Let the remote record the change first, with nyl reconcile -e <env> --unit <unit> after the change is committed, or undo the local effects.

The report lists the units discarded and the local commits dropped. When the branches already follow the remote, nothing changes. State that lives on the clone’s own branches, without a remote, exits 1 with NYL-STATE-RESET-UNSUPPORTED.

nyl state restore

Section titled “nyl state restore”

Restores the content of an earlier state commit after local branches were pushed to the remote state refs by hand. Such a push puts Nyl-Local commits at the remote tips, and every state-writing command then exits 1 with NYL-STATE-LOCAL-TIP, naming the last commit without the trailer; pushed local transitions are never accepted, because their source commits may be unpushed or dirty.

--to takes a full commit ID of the desired or the observed state ref. The command pairs it with the other ref’s commit of the same transition, the one with the same Nyl-Run-Id trailer, else the one its Nyl-Read-Desired or Nyl-Read-Observed trailer names, so it never restores a desired and observed pair that did not exist together. A commit outside the state refs, a Nyl-Local commit, a transition commit of another environment sharing the refs through path, or one whose pair cannot be found exits 1 with NYL-STATE-RESTORE-INVALID.

It takes the lease and writes one desired and one observed commit on top of the current tips, so protected branches need no force push. The commits restore every unit document, artifact, observation, and attestation of that commit, carry state.yaml forward with a state-restored event, and list the environment’s rejected local commits. Admission is never restored. When the state already holds that content and its tips are not local, nothing changes.

nyl lease break

Section titled “nyl lease break”

Declares the lease holder gone, for example after a forced kill. The holder is the lease, or a live run whose lease ref is already gone. Only an importer takes the broken lease over at once, without waiting for its deadline: nyl reconcile, nyl teardown, or nyl recover -e <env>, which imports the broken run’s results without executing anything. It records who broke the lease and why in its transition commit. Until then every other state writer, such as hold, resume, verify, and the state operations, refuses with NYL-LEASE-BROKEN (exit 2), naming nyl recover -e <env>. A lease that is already broken is reported as such. A holder that is in fact still running can still cause effects, but it can no longer write state.

Options and exit codes

Section titled “Options and exit codes”

All commands take -e/--environment, --reason, --wait-lease <duration> to wait for another run’s lease, --author "Name <email>", and -o json for the operation’s versioned report.

--author names the author and committer of the state commits the command writes. Without it, Nyl uses Git’s user.name and user.email for the project’s repository; without either, the command exits 1 with NYL-COMMIT-IDENTITY-MISSING before changing anything. The commit time comes from the same clock as the command’s other time-based decisions. state reset writes no commit, but still resolves the identity.

They exit 0 when done or when nothing needed to change, 2 while another run holds the lease (NYL-LEASE-HELD), a broken lease waits for its import (NYL-LEASE-BROKEN), or state delete --teardown waits as teardown does, and 1 for every other refusal, including NYL-STATE-DELETED on a deleted location; each error and warning carries a stable code and its fix. SIGINT or SIGTERM during --wait-lease refuses with NYL-RUN-CANCELLED (exit 1) and writes nothing. Every command that writes remote state, except state restore, exits 1 with NYL-STATE-LOCAL-TIP when a state ref’s tip is a pushed local transition.

When state delete --teardown encounters manual units, it accepts the same approval flags as reconcile, including --approve-all. Units requiring a reviewed destroy digest still need an explicit --approve <unit>=<digest>.
