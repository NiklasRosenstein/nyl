Runs

A run reconciles one environment: it renders the environment’s units at one source commit, resolves the references between them, executes the units whose results are missing or out of date in dependency order, and records what happened in one transition commit per state ref. nyl plan shows what a run would do, nyl reconcile performs it, and nyl status and nyl get -e read the result.

Note

Runs support the Command unit kind, multi-environment dependencies, approvals, recovery from runs that died, drift repair, and deletion and holds.

Units

Section titled “Units”

A unit is one step an environment runs, such as a Command. Units are resources of units.gitops.nyl/v1 anywhere in the project. Their envelope, apiVersion, kind, metadata.name, and metadata.labels, is literal, so an Environment’s unitSelector selects them before anything renders. Below the envelope, spec is a Nyl template rendered once per selecting Environment, with the Environment’s values as values.

Unit names are unique per environment, and a unit’s name is its identity for references and receipts. enabled: false, or a document that renders to nothing, takes a unit out of the environment.

Common fields every kind shares:

FieldMeaning
enabledfalse leaves the environment’s ownership set. Default true.
outputsThe outputs the unit declares, each with a type and optionally sensitive: true.
dependsOnUnits that must have a current receipt first, for ordering without a data reference.
timeoutThe deadline of one execution, at most 7d.
envpassthrough, the names of runner variables the unit may read, and secrets, mapping variable names to project secret keys. Missing credentials stop the unit before execution.

References between units

Section titled “References between units”

{fromUnit: {unit: <name>, output: <output>}} stands for an output of another unit’s current receipt, and {fromUnit: {unit: <name>, artifact: <name>, pointer: /…}} for a value inside one of its artifacts. A reference replaces the whole value it stands for, at any depth of the fields a kind accepts references in, such as a Command’s values. References add a dependency on their producer, as dependsOn does. A cycle is rejected with NYL-DEPENDENCY-CYCLE, and a reference to a unit the environment does not select with NYL-DEPENDENCY-UNKNOWN.

A consumer whose producer has no current receipt is blocked: it keeps its previous resolution and does not execute in this run. When the producer executes in the same run, Nyl resolves again and the consumer runs in a later wave. A sensitive output can never be referenced.

nyl validate checks references without state, as plan and reconcile do before reading it: the producer must exist and declare the output as non-sensitive. An artifact reference is checked only for the producer’s existence.

References and dependsOn entries require a current receipt, evidence published. Requiring evidence: attested or naming attestations is rejected with NYL-ATTESTATIONS-UNSUPPORTED until units record attestations in a later milestone, rather than accepting a receipt without them.

Source commit

Section titled “Source commit”

Every run works at one source commit, S. The Environment’s source decides it: omitted, S is the commit of the worktree you run from; with revision, the tip of that ref; with revision and commit, the pinned commit. --source overrides S for one plan or reconcile; the transition commit marks the override, and the next run uses the Environment’s source again.

Nyl reads the Environment’s source, state, protectedRefs, allowUnprotectedSource, and admission fields, with the defaults of its EnvironmentGroup, from the worktree you run from, because they decide S and where state lives. Everything else, the units, their templates, and the Environment’s values, is rendered from a fresh checkout of S, so uncommitted changes never reach a run.

  • S must be reachable from one of the Environment’s protectedRefs, by default the repository’s default branch. allowUnprotectedSource: true lets an environment such as dev run from any commit, for example a feature branch.
  • A pinned commit, of the Environment’s source or of a unit’s source fields, must be reachable from protectedRefs or from its own revision. allowUnprotectedSource never waives this.
  • An unreachable commit fails the run with NYL-SOURCE-UNREACHABLE, naming the commit and the refs searched.

A Command unit runs from S. Each unit source field can name its own revision and commit, in this repository or a declared GitRepository (or inline repository). A remote source requires revision; its paths are relative to that checkout’s root. Local source paths stay relative to the directory containing nyl.toml, or worktree-rooted with /. Named image contexts may therefore read different commits and repositories in one build. Resolution records each field’s commit and normalized path, and reads the same bytes when fingerprinting, planning, executing, verifying, and tearing down.

Image and infrastructure drivers declare the paths they read. Their private checkouts contain those paths, including declared local modules and variable files, plus this repository’s configuration directory (nyl.toml alone when it sits at the repository root). Unrelated repository files are not checked out. Command units retain a full checkout because their files list determines freshness without restricting everything the command may read. Changing a source commit alone does not re-run a unit when its recorded input bytes are unchanged.

Worktree inputs

Section titled “Worktree inputs”

For local development, reconcile uncommitted declarations and input files with:

Nyl snapshots Git-visible tracked and untracked files once, preserving deletions and executable modes. Ignored untracked files are excluded. Internal symlinks are preserved without following their targets; input paths cannot traverse symlinks. HEAD and the staging index stay untouched. Discovery, preflight, rendering, and all execution waves use that immutable snapshot; subsequent edits belong to the next run. Explicitly pinned unit sources keep their declared commits. Drivers may require committed source; --worktree refuses those units. The flag requires exactly one named environment and conflicts with --source, label selectors, and group selectors.

State and run checkpoints archive the snapshot and its source ancestry, including Git-visible uncommitted files, in the configured state repository. Recovery and teardown can retrieve those inputs from another clone after the working files are gone. Choose a local state repository for disposable experiments, as in the local Docker example. --local independently keeps state transitions on the clone’s local branches.

NYL-SOURCE-WORKTREE, the transition’s worktreeSource summary, and the reserved refs/nyl-worktrees/ source revision identify the run’s provenance. Those refs cache snapshots locally; the state history retains the archived inputs. Nyl does not automatically garbage collect snapshots or compact that history. Snapshots cannot publish Kubernetes trees or count as clean committed-source promotion evidence. Commit changes and reconcile without the flag for that evidence.

Following execution

Section titled “Following execution”

Reconcile prints a start and end message for every dispatched unit. End messages include the result and elapsed time, with a short reason when the unit fails. Tool output is labelled with the environment/unit address, so concurrent units remain distinguishable. Progress and tool transcripts go to stderr; JSON reports stay on stdout.

The final summary follows dispatch order, with names breaking ties in a parallel wave. Units that did not run follow in dependency order, and teardown lists consumers before their producers. JSON reports provide this order in unitOrder alongside the units map.

Execution keys and receipts

Section titled “Execution keys and receipts”

Each execution records a receipt in the observed state: the execution key it ran with, its outputs, its artifacts, and the receipts it read through references. A unit executes when it has no receipt whose key matches its current execution key, or when a receipt it read is no longer current. The execution key alone decides: a producer recreated with a new identity and the same outputs leaves its consumers current, and a unit that must run again whenever a producer is recreated says so in its inputs, for example by reading an output that changes with every creation. A unit whose latest drift observation is drifted runs again too, as Recovery describes.

The execution key is a digest of everything that decides what the unit does: its resolved spec, including the values its references resolved to, the content its kind reads, such as a Command’s files and fingerprint, and the names of the variables it may read. A change outside those inputs, such as a new commit that touches other files, never runs a unit again. A repeated reconcile with no changes executes nothing and writes no commit.

Waves

Section titled “Waves”

nyl reconcile:

  1. takes the environment’s lease;
  2. resolves every unit at S against current receipts;
  3. executes the ready units, independent units in parallel up to --concurrency (default 4), and checkpoints each result on the run ref. Each of the --concurrency slots keeps one checkout for the run and resets it to the next unit’s effective commit, removing untracked and ignored files, so a unit sees exactly what a fresh checkout of its commit holds. Before it starts each unit, the run reads holds that nyl hold sent it, and starts no held unit;
  4. resolves again at the same S, because new receipts unblock dependents, and repeats from step 3 until nothing is ready;
  5. carries out lifecycle work: units that left the ownership set, and teardowns an operator requested, are torn down, retained, released, or dropped, consumers first (Deletion and holds);
  6. writes one transition commit per state ref, then releases the lease.

A failed execution records a condition and keeps the unit’s previous receipt. An execution that may have had effects without completing, such as one that passed its timeout, is uncertain. A retryable failure runs again at the next reconcile; a non-retryable failure, and an uncertain unit whose kind does not converge, wait for nyl recover. Recovery explains conditions, recovery policies, and how a run takes over from a run that died, and the Command guide describes how a Command converges. --unit executes only the named units and does no lifecycle work; resolution still covers the whole environment, and a named unit whose dependency has no current receipt stays blocked. --leaving does only the lifecycle work.

A unit that fails, becomes uncertain, waits for an approval, or is blocked does not stop the units that do not depend on it: a run reconciles everything it can. With --fail-fast, the run starts no further unit after the first failure, uncertain outcome, or approval wait; units already running finish, and the run still checkpoints them and writes its transition commit. The units it did not start are blocked with the reason --fail-fast stopped the run after <unit>, and it warns with NYL-RUN-STOPPED.

Transition commits

Section titled “Transition commits”

A reconcile that changes state writes one commit to each state ref it changes, and a reconcile that changes nothing writes none. The message starts with a headline and a machine-readable summary of every unit’s result, followed by trailers naming the run, the source commit, the state commits it read, the runner, and the evaluation time:

Each unit’s result is one of:

ResultMeaning
currentThe unit already had a current receipt.
executedThe unit ran, with this executionKey.
importedA run that died or lost its lease checkpointed the unit with the same execution key, and that checkpoint, from run, became its receipt.
recoveredThe unit was uncertain, and this run executed it again or found its effects applied.
failedThe execution failed, with its category and whether it is retryable.
uncertainEffects may have happened; the unit waits for its recovery policy or nyl recover.
blockedA reference or dependency has no current receipt, a held unit it depends on has none, or --fail-fast stopped the run first.
awaiting-approvalThe unit needs an approval, such as --approve in a --local run, including a drifted unit that is not safe to re-run.
driftedThe unit’s receipt is current but drifted, and this run did not repair it (driftRepair: manual, or not named by --unit).
heldThe unit is held; the detail names the source commit whose changes wait, and a pending teardown.
pending-teardownThe unit left the ownership set and its teardown has not started: it waits for --allow-teardown, its deleting dependents, readiness, or an approval.
tearing-downThe unit’s teardown started and continues later, such as a publication waiting under its teardownWait.
removedThe unit was torn down, and its files were removed.
retainedThe unit left the ownership set with deletionPolicy: Retain and became a tombstone.
releasedThe unit’s resources were left in place, because its kind cannot tear down, and its state was removed or held.

held, drifted, pending-teardown, and tearing-down make a reconcile exit 2, because work remains; a held unit whose teardown request a nyl teardown only recorded exits 0. removed, retained, and released exit 0.

imported lists the units whose receipts came from checkpoints of earlier runs, and recovered the units this run marked uncertain while taking over or recovered by executing them again. leaseBroken appears when the run took over a lease that nyl lease break broke. driftRepaired lists the units the run executed again because they drifted, and reapplied records who forced which units with --reapply, and why; each appears only when it is not empty:

Lifecycle work adds its details: released and retained list the units and what they left in place, allowDependents the tombstones an override passed, confirmedRemoval how a publication’s teardown wait ended, incomplete what a teardown may have left behind, sourceOverride a teardown’s --source, teardownRequested the held units whose teardown request was recorded, and held the units a hold reached during the run. The headline counts each result except current.

State commits are authored by --author "Name <email>", else by Git’s user.name and user.email; without either, nyl reconcile exits 1 with NYL-COMMIT-IDENTITY-MISSING. Commands that only read state, plan, status, and get, need no identity.

Approvals

Section titled “Approvals”

A unit with approval: manual executes only with an invocation approval. --approve <unit> authorizes its initial desired execution key; if references resolve to a different key later in the run, the unit waits for a new approval. An initially blocked unit cannot be approved for a key that does not yet exist. A unit excluded by --unit cannot be approved.

For a kind that reports change digests, approval: {mode: manual, bind: plan} accepts --approve <unit>=sha256:…. The driver recomputes the plan before effects and waits with the new digest if it changed. The same rule covers destroy plans. Without a digest, the approval is recorded as unreviewed; requireDigest: true refuses it. --approve-all approves candidates without reviewed digests, so those requiring a digest still wait.

Receipts and transition summaries record approvers, their source, the digest, and whether it was reviewed. --approved-by alice,bob --approval-source <url> records identity: asserted. A workstation run otherwise records the Git user as local. In CI, a configured lookup or GitHub lookup records verified; without a lookup or token Nyl records the CI run source with no approver. These are audit identities: the CI gate controls who can authorize the invocation.

Configure other CI systems with an optional hook:

The hook runs in the project directory with NYL_ENVIRONMENT, NYL_APPROVAL_UNITS (a JSON array of explicitly approved names), and NYL_APPROVAL_DIGESTS (a JSON object mapping names to digests or null). It prints {"by": ["alice"], "source": "production gate", "url": "https://ci.example/run/1"}. Nyl records the command and result as verified. An invalid response, failure, cancellation, or 30-second timeout stops the invocation before unit effects with NYL-APPROVAL-INVALID. Explicit identity flags take precedence over lookups.

In GitHub Actions, GITHUB_TOKEN (or GH_TOKEN) with Actions read permission allows Nyl to query the run review history. It records approved reviewers for the GitHub environment whose name matches the Nyl environment. The token remains in the lookup adapter and is never automatically admitted to unit tools.

Multi-environment runs

Section titled “Multi-environment runs”

plan, reconcile, status, and verify accept repeated -e, a label selector with -l, or an EnvironmentGroup with -g:

Environments run in dependency order, producers first, with ties by name. Each environment resolves its own source, takes its own lease when writing, and writes its own transition commit. Every selected environment runs even when an earlier one fails or waits. The invocation exits with the most severe category across its environment report sections.

A cross-environment reference uses the producer’s declared environment:

dependsOn also accepts {environment: infra, unit: network}. The producer must select and enable the unit, and its receipt must be current. A run reads each producer’s state once, without its lease; provenance records that producer’s observed commit. A consumer run before its producer has a receipt waits. In one invocation, consumers read the receipts that preceding producer runs just wrote. References outside the selection read existing state. Environment dependency cycles fail validation.

If a selected producer fails or waits, including when its lease is busy, consumers wait instead of using its old receipts. Independent units still run.

Planning reads current receipts rather than preview outputs. If a preceding producer plan changes a referenced unit, the consumer plan waits and names that producer’s planned change, even when --unit hides it from the producer’s report. A producer cannot be torn down while other environments’ stored desired units reference it unless --allow-dependents permits that action.

In a selection containing several environments, unit options must name their environment: --unit services/api and --approve services/api=<digest>. Unqualified names and names outside the selection fail. --allow-teardown and --allow-dependents apply to all selected environments; --source takes exactly one environment. Deliberate actions such as teardown, hold, recover, and state commands continue to take one environment.

Stored incarnations protect their resource ownership until removed, including held units and units awaiting teardown whose source no longer declares them. If an environment’s state cannot be read, environments that claim native resources are refused until access returns; independent units without resource claims can still run.
