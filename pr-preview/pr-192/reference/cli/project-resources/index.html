get and update

Inspect project resources

Section titled “Inspect project resources”

nyl get reports GitOps control resources, Environments, and units discovered in project source:

Plural resource names are canonical and singular aliases select the same kind. An optional name filters the result. Output contains the resource name, source file and document, and concise kind-specific coordinates. The command does not render workloads, resolve remote sources, or contact Kubernetes.

Each kind prints one table row per resource:

CONTEXT is the Cluster’s spec.live.context, PUBLICATION the target’s repository and revision, and PROJECT the ApplicationGroup’s AppProject, marked (generated) when Nyl derives it.

Inspect environment state

Section titled “Inspect environment state”

With -e <environment>, nyl get reads that environment’s orchestration state instead of source. It only reads: it needs read access to the state repository, never takes the lease, and needs no commit identity.

  • get units -e joins desired and observed state into one row per unit: its kind, its state, whether its latest receipt is current, the run of its latest receipt or condition, and a detail such as what a blocked unit waits for or the changes a held unit keeps pending. A held marker, which has no kind, shows - as its kind, and a held unit with a condition shows it, such as held (uncertain). -o wide adds the teardown readiness of units whose kind reports teardown settings, such as a KubernetesPublication: ready, or incomplete: with the unmet requirements, and - for other kinds.
  • get unit <name> -e <env> -o yaml|json prints exactly the persisted {desired, observed} documents, never a synthesized merge. --desired or --observed prints only one of them.
  • get output <unit>/<output> and get artifact <unit>/<name> --pointer … print one value for scripts and resolve exactly like the matching fromUnit reference: the pointer is relative to the artifact’s spec, and only a current receipt counts. When the reference would not resolve, they print nothing and exit 1. --allow-stale prints the latest receipt’s value with the warning NYL-REFERENCE-STALE instead.
  • --state-revision <commit> reads state as of an earlier state commit.
  • --local reads this clone’s local state branches, including nyl reconcile --local runs, instead of the remote state. It cannot be combined with --state-revision.
  • -o selects table (default), wide, yaml, json, or name.

Every form takes the project directory, or a path beneath it, as its last argument, default .. Document and table forms exit 0 when they can read the requested state and 1 otherwise, for example with NYL-STATE-MISSING.

Update cluster capabilities

Section titled “Update cluster capabilities”

Refresh Cluster.spec.kubernetes from the live cluster:

The explicit context wins over Cluster.spec.live.context. The update changes only the selected Cluster document and preserves the rest of a shared YAML file. --check reports drift without writing.

Update source locks

Section titled “Update source locks”

Resolve remote ApplicationGroup sources, fromGit Release inputs, Environment sources, and native unit sources (including named image contexts), and update their full commit locks:

A group name selects that ApplicationGroup and --target selects one DeploymentTarget’s fromGit locks; without either, every lock is updated. The filters choose which locks move, never where: each lock’s destination depends only on the lock, so a filtered update agrees with an unfiltered --check. Every lock moves to the head of its revision. Each repository is fetched once per run. Locks are edited in place by their position, so write source locks and fromGit bindings in block style. Unit source locks require literal repository coordinates, revisions, and commits; unfiltered updates include them, while group and target filters select only the named control resources. A revision without a commit follows its tip and has no lock to refresh.

Mutable revisions must refresh successfully before a lock is reported current or updated. Immutable commit rendering can use an existing local cache.
